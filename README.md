Данный репозиторий предназначен для выполнения заданий по дисциплине "Инжиниринг данных"

[Датасет на Google Drive](https://drive.google.com/drive/folders/1WtNE7mtGj4gSK8cTiUReBqz30Pr-MNCD)

**Размер файла** `Oil_Pipeline_Accidents.csv` **≈ 908 КБ**

**Содержание:** по каждому инциденту дата и время, оператор и трубопровод, причина аварии, тип разлитой жидкости и объем потерь, число пострадавших и погибших, связанные затраты

## Развертывание окружения

Требуется Python 3.9+. Все зависимости описаны в `pyproject.toml`: в `dependencies` — то, что нужно пакету `etl`, в dev-блоке `[project.optional-dependencies] dev` — служебные библиотеки (pytest, ruff, ядро Jupyter и seaborn для ноутбука, httpx и BeautifulSoup для скрэпинга из ДЗ №4).

```bash
# 1. Создайте виртуальное окружение в папке проекта
python3 -m venv .venv

# 2. Активируйте его
source .venv/bin/activate      # macOS / Linux
.venv\Scripts\activate         # Windows

# 3. Обновите pip (для установки из pyproject.toml нужен pip 21.3+)
python -m pip install --upgrade pip

# 4. Установите пакет etl с зависимостями
pip install -e .               # только ETL
pip install -e ".[dev]"        # ETL + служебные библиотеки (тесты, ноутбук, скрэпинг)
```

## Домашнее задание №7 — запись в базу данных

Работа разделена на два скрипта:

- `scripts/creds_to_env.py` — читает данные для подключения из таблицы `access` в SQLite-файле и записывает их в файл `.env` в корне проекта (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`);
- `scripts/write_to_db.py` — берет доступы только из `.env` и записывает первые 100 строк датасета в таблицу `bulatovaks` базы `homeworks`. Если таблица уже существует, скрипт остановится, чтобы не перезаписать данные.

Установите зависимости (см. «Развертывание окружения»). Положите полученный файл SQLite вне репозитория и из корня проекта перенесите доступы в `.env`:

```bash
python scripts/creds_to_env.py /полный/путь/к/creds.db
```

Файлы `.env` и `creds.db` добавлены в `.gitignore` и не должны попадать в репозиторий. Если датасета в папке `data/` еще нет, сначала запустите `python data_loader.py`. Затем выполните:

```bash
python scripts/write_to_db.py
```

После записи скрипт проверяет количество строк и выводит результат.

## Домашнее задание №8 — пакет etl

Весь цикл подготовки данных собран в пакет [`src/etl`](src/etl): скачивание сырого датасета, проверка, преобразование, повторная проверка и загрузка результата (не больше 100 строк) в PostgreSQL. Пакет самодостаточен: он не импортирует `data_loader.py` и скрипты из `scripts/`, а лучшие решения из них (скачивание с проверкой файла, перенос доступов в `.env`, запись в транзакции с проверкой числа строк) встроены в его модули. Преобразования и проверки взяты из выводов EDA (ноутбук, раздел 9).

### Как работает

```text
extract ──> validate_raw ──> transform ──> validate_processed ──> load
Google Drive   схема Pandera    типы, чистка,  схема Pandera +       Parquet (весь датасет)
или --source   на входе         флаги качества лог проблем источника  + PostgreSQL (≤ 100 строк)
```

1. **extract** — скачивает CSV с Google Drive через `gdown` в `data/raw/` (если корректной копии там еще нет) или читает локальный файл из `--source`. Проверяет, что скачан именно CSV, а не HTML-страница Google Drive.
2. **validate_raw** — проверяет источник: все 48 столбцов на месте, `Report Number` уникален и состоит из 8 цифр, флаги только `YES`/`NO`, даты соответствуют своим форматам, код штата из двух букв.
3. **transform**:
   - даты парсятся каждая со своим форматом (у аварии AM/PM, у остановки и перезапуска 24 часа);
   - флаги `YES`/`NO` переводятся в nullable `boolean`, поэтому пропуск остается пропуском, а не становится `False` (ошибка из ДЗ №3, найденная в EDA);
   - пропуски в полях о пострадавших заменяются на 0, счетчики людей переводятся в `Int64`; у эвакуаций пропуск остается, потому что поле появилось в форме не сразу;
   - убираются лишние пробелы в названиях (`MOBIL  PIPE  LINE` → `MOBIL PIPE LINE`), у округов — суффиксы `COUNTY`/`PARISH`;
   - если у долготы потерян минус и с минусом точка попадает в США, знак исправляется;
   - добавляются `downtime_hours` и флаги качества: `is_shutdown_before_accident`, `is_shutdown_same_minute`, `is_zero_costs`, `is_outside_usa`, `is_incomplete_year`. Записи не удаляются: флаг показывает, для каких расчетов запись не годится;
   - имена столбцов переводятся в `snake_case`, чтобы с ними было удобно работать в SQL.
4. **validate_processed** — схема Pandera для результата: типы, неотрицательные объемы, затраты и счетчики, диапазоны координат, `all_costs` = сумма затрат, `net_loss` = утечка − собрано, год совпадает с датой, нет взрыва без возгорания, перезапуск не раньше остановки. При нарушении ETL останавливается и печатает, какие проверки не прошли и сколько раз. Известные проблемы источника (флаги из шага 3) ошибкой не считаются, они выводятся в лог предупреждениями.
5. **load** — сохраняет весь обработанный датасет в `data/processed/oil_pipeline_accidents.parquet` и записывает первые по дате аварии `--rows` строк (по умолчанию и максимум 100) в таблицу `bulatovaks` базы `homeworks`. Запись и проверка числа строк идут в одной транзакции: если что-то не так, изменения откатываются.

### Запуск

После установки (см. «Развертывание окружения») ETL запускается из корня репозитория одним из способов:

```bash
etl --help            # консольная команда из pyproject.toml
python -m etl --help  # то же самое через модуль
```

Первый запуск: передайте SQLite-файл с доступами, ETL перенесет их в `.env` и пройдет весь цикл. Таблица `bulatovaks` уже создана в ДЗ №7, поэтому ее нужно перезаписать:

```bash
etl --creds-db /полный/путь/к/creds.db --if-exists replace
```

Дальше доступы берутся из `.env`, путь к `creds.db` больше не нужен:

```bash
etl --if-exists replace            # перезаписать таблицу свежими данными
etl --rows 50 --if-exists replace  # записать 50 строк вместо 100
etl --skip-db                      # без базы: только скачивание, проверки и Parquet
etl --source ~/Downloads/Oil_Pipeline_Accidents.csv --skip-db  # локальный файл вместо Google Drive
```

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--rows N` | `100` | сколько строк записать в базу, от 1 до 100 |
| `--table NAME` | `bulatovaks` | таблица в базе |
| `--if-exists {fail,replace}` | `fail` | что делать, если таблица уже есть: остановиться или перезаписать. Дописывания нет, чтобы в таблице не оказалось больше 100 строк |
| `--creds-db PATH` | — | SQLite-файл с доступами; перед запуском они записываются в `.env` |
| `--source PATH` | — | локальный CSV вместо скачивания с Google Drive |
| `--data-dir PATH` | `data/` | папка для сырого и обработанного датасета |
| `--skip-db` | — | не писать в базу |
| `-v`, `--verbose` | — | подробный лог и traceback при ошибке |

ETL печатает в лог каждый шаг: сколько строк прочитано, какие проверки пройдены, сколько записей с известными проблемами источника помечено и сколько строк записано в базу.

## Структура проекта

```text
Data_Engineering/
├── src/
│   └── etl/                  # ДЗ №8 — пакет ETL
│       ├── __init__.py       # описание пакета и версия
│       ├── __main__.py       # запуск через python -m etl
│       ├── main.py           # CLI: разбирает аргументы и запускает весь цикл
│       ├── config.py         # пути, ID файла на Google Drive, таблица, списки столбцов
│       ├── extract.py        # скачивание сырого CSV с Google Drive и чтение
│       ├── transform.py      # типы, чистка, исправление координат, флаги качества
│       ├── validate.py       # схемы Pandera для сырых и обработанных данных
│       ├── load.py           # Parquet и запись до 100 строк в PostgreSQL
│       ├── creds.py          # доступы к базе: SQLite-файл -> .env -> подключение
│       └── utils.py          # snake_case и проверка «точка в США»
├── tests/                    # pytest: проверки пакета etl
├── notebooks/
│   └── EDA.ipynb             # ДЗ №5 и №6 — разведочный анализ и визуализация
├── scripts/
│   ├── scrap_site.py         # ДЗ №4 — скрэпинг каталога podrygka.ru
│   ├── creds_to_env.py       # ДЗ №7 — перенос доступов в .env
│   └── write_to_db.py        # ДЗ №7 — запись 100 строк в базу
├── data_loader.py            # ДЗ №2 и №3 — загрузчик и приведение типов
├── data/                     # создается при запуске, в git не коммитится
│   ├── raw/                  #   сырой CSV (etl)
│   └── processed/            #   обработанный Parquet (etl)
├── pyproject.toml            # зависимости: etl + dev-блок, команда etl, настройки pytest и ruff
├── .env                      # доступы к базе, создается etl --creds-db, в git не коммитится
└── .gitignore
```

Скрипты из `scripts/` и `data_loader.py` оставлены как результаты прошлых ДЗ, пакет `etl` от них не зависит.
